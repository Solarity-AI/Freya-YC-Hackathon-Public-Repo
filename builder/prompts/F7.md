Facet F7: situations, outcomes, notes and multi-product rules. Intents are extracted by another call (facet F5)
and refer to situations by the shared situation ids: define every shared id the brief's rules can reach.

- situations: every situation id used by any facet (see the shared list; define all the brief's outcome table
  supports): outcome (close outcome enum value), reason (the close reason from the brief's table; "" when the table
  gives no reason for that outcome, which means no reason is sent at all), queue (transfer queue enum value for
  transfer situations, else ""), note_reason (note reason enum value used when a product ends in this situation,
  else "").
- outcomes.precedence: ordered rows {when, use}, evaluated top-down, first match wins. when: transfer_done |
  any_promise_recorded | call_situation | all_products:S_X | any_product:S_X | else. use: transfer_situation |
  call_situation | situation:S_X | first_product_excluding:S_A[,S_B]. A typical order: transfer_done ->
  transfer_situation (when a transfer after a recorded promise closes as transferred); any_promise_recorded ->
  situation:S_PROMISE; call_situation -> call_situation; all_products:S_PAID -> situation:S_PAID;
  else -> first_product_excluding:S_PAID. Follow the brief's own aggregation rules when it gives them.
  reasonless_outcomes: outcomes sent without any reason. unresolved_product_situation: what an unresolved product
  counts as (usually S_REFUSED_EXHAUSTED).
- notes: enabled (true only if the brief asks for add_note; false when it says it is never used), scope (product |
  call), when "no_promise_recorded", reason_from "product_situation", skip_if_transfer, text ("" unless the brief
  gives a note text).
- multi_product: state_all_first, ask_all_today_first, order "api", attempts_per_product, one_date_for_all
  ("clamp_to_own_deadline_and_say"), readback_together, hardship_applies_to ("all_remaining" or
  "current_product"), dispute_or_paid_continues (true when a dispute/paid on one product lets the call continue with
  the others), clamp_line (uses <product> and <deadline>). Use the brief's multi-product rules; if it is silent,
  omit this key.
